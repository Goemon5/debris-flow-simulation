# 90-Case CFD Simulation Campaign for GNN Training Dataset Generation

## 【総括】エグゼクティブサマリー

本シミュレーションキャンペーンは、災害現場における匂い拡散予測を目的とした2段階物理情報GNN（GNN+PINN）モデルの学習用教師データセット生成のために実施されました。30種類の多様な瓦礫パターン × 3種類の戦略的匂い源配置 = 合計90ケースの高忠実度CFDシミュレーションを自動化実行し、GNNモデルの汎化性能と頑健性を獲得するための世界唯一の包括的データセットの生成に成功しました。

このシミュレーション完了により、本研究における最も技術的に困難なデータ生成フェーズが完了し、後続の機械学習フェーズの成功を支える揺るぎない土台が構築されました。

## 【目的】なぜ90ケースもの大規模計算が必要だったか

### 30の瓦礫パターンによる幾何学的多様性の確保

実際の災害現場では、建物の倒壊や土砂崩れにより、予測不可能な複雑な障害物配置が生じます。GNNモデルが未知の瓦礫形状にも対応できる汎化能力を獲得するため、以下の戦略により30種類の多様なパターンを生成しました：

- **形状の多様性**: 直方体、円柱、不規則形状の組み合わせ
- **配置の多様性**: 集中配置、分散配置、線形配置など
- **密度の多様性**: 疎な配置から密集配置まで
- **スケールの多様性**: 小型障害物から大型構造物まで

### 3つの匂い源による空間的頑健性の獲得

匂いの発生源位置が変わっても安定して予測できる能力をモデルに与えるため、計算領域内に以下3つの戦略的位置を設定しました：

- **Center (7.5, 7.5, 0.5)**: 計算領域中央部での拡散パターン学習
- **Upwind (5.0, 7.5, 1.0)**: 風上位置からの典型的拡散パターン学習  
- **Side (7.5, 5.0, 1.5)**: 側方位置での複雑な拡散パターン学習

この組み合わせにより、GNNモデルは匂い源位置に依存しない普遍的な拡散予測能力を獲得できます。

## 【技術概要】2段階シミュレーションワークフロー

本研究では、計算の安定性と効率性を両立するため、革新的な「2段階シミュレーション」アプローチを採用しました。

### ステップ1：定常流れ場計算（simpleFoam）

まず、各瓦礫パターンに対してsimpleFoamソルバーを使用し、安定した背景となる「風の地図」を計算します：

```bash
# 各pattern_XX/ディレクトリで実行
simpleFoam
```

- **目的**: 瓦礫による流れの偏向・乱れを含む定常速度場・圧力場の取得
- **出力**: `pattern_XX/5/U` (速度場), `pattern_XX/5/p` (圧力場)
- **重要性**: 匂い拡散の基盤となる流体力学的環境の確立

### ステップ2：過渡的匂い拡散計算（scalarTransportFoam）

ステップ1で得た静的な流れ場上で、scalarTransportFoamソルバーを使用し、匂いが時間と共に広がる様子を計算します：

```bash
# run_all_90_cases.shによる自動実行
scalarTransportFoam
```

- **目的**: 流れ場に支配された匂い濃度の過渡的変化の計算
- **出力**: 時系列濃度場データ `T` (0.5秒間隔、5秒間)
- **重要性**: GNN学習の主要ターゲットとなる濃度予測データの生成

## 【主要パラメータ】シミュレーションの仕様

| パラメータ | 値 | 説明 |
|-----------|---|------|
| **ソルバー** | scalarTransportFoam | OpenFOAM 10パッシブスカラー輸送ソルバー |
| **乱流モデル** | RANS (simpleFoam結果を使用) | 定常乱流解析による安定した流れ場 |
| **シミュレーション時間** | 5.0秒 | 匂い拡散の十分な発達を捉える時間設定 |

| **出力間隔** | 0.5秒 (100ステップ毎) | 時系列学習に適した適度な解像度 |
| **分子拡散係数** | 2×10⁻⁵ m²/s | 現実的な匂い物質の拡散特性 |
| **匂い源強度** | 1×10⁵ kg/m³/s | 十分な濃度勾配を生成する源項設定 |
| **匂い源領域** | 半径0.3mの球領域 | 現実的な点源近似 |
| **境界条件** | 流入固定値、流出勾配ゼロ | 物理的に妥当な境界設定 |

## 【自動化システム】run_all_90_cases.sh の機能解説

今回の成功の鍵は、高度に自動化された生産レベルのスクリプト`run_all_90_cases.sh`の開発です。

### ループとパラメータ化による動的ケース生成

```bash
# 外側ループ：30パターン
for i in $(seq -f "%02g" 1 30); do
    pattern_dir="pattern_$i"
    
    # 内側ループ：3つの匂い源
    for source_name in $SOURCES_LIST; do
        # 各ケースの設定ファイルを動的生成
        create_fv_options "$case_dir" "$source_coords" "$source_name"
        create_topo_set_dict "$case_dir" "$source_coords" "$source_name"
    done
done
```

### 効率的な並列実行システム

```bash
MAX_JOBS=4  # システムリソースに応じて調整可能
wait_for_slot()  # ジョブスロット管理機能
```

- **並列度制御**: 最大4つのシミュレーションを同時実行
- **リソース管理**: メモリ・CPU使用量の適切な制御
- **ジョブ追跡**: 実行中・完了したジョブの状態管理

### 体系的な出力管理

```bash
# 命名規則の統一
case_name="${pattern_dir}_${source_name}"
case_dir="$RESULTS_BASE_DIR/$case_name"
log_file="$LOG_DIR/${case_name}.log"
```

- **結果ディレクトリ**: `simulation_results_90cases/pattern_XX_SOURCE/`
- **ログ管理**: `logs_90cases/pattern_XX_SOURCE.log`
- **状態監視**: リアルタイム進捗表示・エラー検出

### Dockerコンテナ化による環境整合性

```bash
docker run -dit --name "$container_name" \
    -v "$(pwd):/work" \
    -w "/work/$case_dir" \
    openfoam/openfoam10-paraview510
```

- **環境統一**: OpenFOAM 10の一貫した実行環境
- **再現性**: コンテナによる計算環境の固定化
- **スケーラビリティ**: 異なるシステムでの同一実行環境

## 【成果物】出力データ仕様

本シミュレーションにより、以下の高品質なデータセットが生成されました。各データはGNN学習において特定の役割を果たします：

### ステージ1教師データ（流れ場）
- **`U` (速度場)**: 3次元ベクトルフィールド [m/s]
  - **役割**: GNN第1段階での速度予測学習
  - **特徴**: 瓦礫による流れの偏向・加速・減速パターン
  
- **`p` (圧力場)**: スカラーフィールド [Pa]
  - **役割**: 流体力学的整合性の保証
  - **特徴**: 障害物周りの圧力分布パターン

### ステージ2教師データ（濃度場）
- **`T` (濃度場)**: 時系列スカラーフィールド [kg/m³]
  - **役割**: GNN第2段階での濃度予測学習（主要ターゲット）
  - **時間解像度**: 0.5秒間隔×11時点（0秒～5秒）
  - **特徴**: 複雑な障害物群による匂い拡散・混合パターン

### メタデータ
- **幾何学データ**: 各パターンの瓦礫配置情報（STLファイル）
- **ログデータ**: 各シミュレーションの収束履歴・最大濃度値
- **設定データ**: 各ケースの境界条件・物理パラメータ

### データフォーマット仕様
- **ファイル形式**: OpenFOAM ASCII形式（高精度・可読性）
- **ディレクトリ構造**: 
  ```
  pattern_XX_SOURCE/
  ├── 0/    # 初期条件
  ├── 0.5/  # 0.5秒時点
  ├── 1/    # 1.0秒時点
  ├── ...
  └── 5/    # 最終時点（U, p, T全て含む）
  ```
